TagKit for Jekyll

A GitHub Pages theme you turn on with one line of config: no CSS, no classes, and pages in plain Markdown.

Quick start View on GitHub

What you get

The theme is plain layouts. TagBrush.css styles the page and TagAction adds behavior. Both load from a CDN, so there is nothing to build or install.

  • Light and dark mode, readable text width, styled tables, footnotes, task lists, and code highlighting (Rouge, colored by TagBrush.css).
  • A top bar with your site title and pages. The current page is marked for screen readers and styled.
  • A blog. The home page lists posts as cards. Posts show the author and date, with links to the previous and next post.
  • An optional table of contents beside a page or post (toc: true) that follows your reading.
  • Copy buttons on code, sortable tables, and "#" links on headings, from TagAction. Everything still works with JavaScript off.

It is part of TagKit. See the gallery for templates and the other themes.

Quick start

Add these lines to your site's _config.yml. That is all GitHub Pages needs.

# _config.yml
remote_theme: kovirlabs/tagkit-jekyll
plugins:
  - jekyll-remote-theme

Then write your pages and posts in Markdown. Don't add CSS, classes, or scripts.

Layouts

LayoutForFront matter
homeThe home page: your content, then a list of posts.title, subtitle, posts_title
pagePages such as About.title, toc: true
postBlog posts. Shows the date and previous and next links.title, author, toc: true
defaultThe page shell. Use it for anything custom.

toc: true adds a table of contents beside the page or post. On the home page, posts_title sets the heading above the post list. It defaults to "Posts".

GitHub Pages picks home, page, and post for you, with its jekyll-default-layout plugin. Elsewhere, set them with defaults:

defaults:
  - scope: { type: posts }
    values: { layout: post }
  - scope: { type: pages }
    values: { layout: page }

An example post

A post in _posts/2026-11-02-a-year-of-saas.md, from the theme's example site:

---
title: What I learned running a tiny SaaS for a year
author: Dana Whitfield
toc: true
---

A year ago I launched a small tool that turns CSV exports into readable reports.

## Charge from day one

The file name gives the date. The ## headings fill the table of contents.

Settings

All settings go in _config.yml and all are optional.

title: Field Notes
description: Short essays on running a tiny software business.
author: Dana Whitfield
lang: en
navigation:
  - { title: Posts, url: / }
  - { title: About, url: /about.html }
tagkit:
  primary_color: "#0f766e"
  date_format: "%B %-d, %Y"
  tagaction: false
  credit: false
title, description, author, lang
The site title and language. The description is the meta description and shows in the footer. The author shows in the footer.
navigation
A list of { title, url } for the top bar. Without it, every page with a title is listed. Order them with nav_order and hide one with nav: false in its front matter.
tagkit.primary_color
The color of links, buttons, and accents.
tagkit.date_format
How post dates are shown. The default is "%B %-d, %Y".
tagkit.tagaction: false
Leaves out the TagAction script.
tagkit.credit: false
Leaves out "Built with TagKit" in the footer.

To add to <head> (a favicon, analytics, {% seo %}, {% feed_meta %}), create _includes/head-custom.html in your site.

For AI agents

Point your coding agent at the theme's llms.txt. It lists the layouts, front matter, and settings in a few lines. For custom layouts and includes, the TagBrush.css guide shows the HTML that looks right.

Tested

CI builds the example site with the github-pages gem, the same Jekyll, kramdown, and plugins GitHub Pages runs. It checks every page with TagCheck: no errors or warnings, WCAG AA contrast in light and dark mode, and no sideways scrolling on phones.
